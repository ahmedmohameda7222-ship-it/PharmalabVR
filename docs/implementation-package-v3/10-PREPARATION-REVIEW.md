# Planner's final preparation review

Decision: ready to execute the specified VR-first research foundation. This is an implementation handoff, not evidence that the product is built or that arbitrary chemical reactions can be predicted correctly. No claim of a perfect architecture or guaranteed model completion in one context window is made.

## Plan

The primary product is an offline Unity VR laboratory, with a full no-headset Windows companion. Both use one native C++ material authority and an explicit IPhreeqc aqueous-equilibrium adapter. The initial supported scientific profile contains water, hydrochloric acid, sodium hydroxide, sodium chloride, acetic acid and sodium acetate. Transfer, amount, overflow, contamination and observations come from state/models rather than branches keyed to an experiment. Instructions subscribe to events without controlling chemistry.

P00–P16 define checkout/bootstrap, native ABI, material/transport, scientific adapter, scheduling, Unity bridge, VR rig, physical tools/spatial UI, indicator/mixing plumbing, desktop journeys, persistence, example lessons, CI/builds, profiling, final review and push. They define source locations, consumed/produced interfaces and acceptance case IDs. The implementer still needs to write/debug code; this package removes product/architecture replanning rather than pretending all implementation judgment can disappear.

## Critic

1. Universal laboratory prediction is not delivered by this engine/profile. More substances, phases, heat, atmosphere and kinetics need data, distinct models and validation. Open manipulation inside supported capabilities is possible; universal chemistry is not an honest acceptance criterion for this handoff.
2. Equilibrium accuracy and graphics do not establish real endpoint/local-mixing accuracy. Optical constants, indicator preparations, tracer data and experimental comparisons remain separate evidence gates. Do not invent them to make both supplied experiments look finished.
3. Source provenance is not deployment proof. IPhreeqc must compile and pass lifecycle/science/performance checks on x64 and ARM64. Upstream version placeholders are recorded separately from the commit; the database stays intact until trimming equivalence is proved.
4. OpenXR is not a promise that every headset works. Simulator/desktop evidence cannot establish physical VR comfort, thermal behavior or reading accuracy. Quest/PICO profiles need their own evidence. The user lacks a headset.
5. Model completion of this scope in one turn cannot be guaranteed. Persistent task/evidence records and commits support one assignment across compactions; authentic tool/license/auth/data blockers remain explicit.
6. JSON ABI and asynchronous equilibrium scheduling have overhead. Budgets, capped queues and profiling are required. Replace hot paths after measurement; never alter calibrated flow to hide performance failures.
7. This profile is Research. Tested software and ideal numeric agreement are not independent experimental validation or university assessment certification.

## Alternatives and long-term assessment

Unity/XRI/OpenXR is retained for tracked-controller interactions, desktop/native development and standalone headset builds. A browser rewrite reopens interaction/platform compromises. Unreal is viable but does not solve scientific data gaps and would discard the frozen tooling/contracts without demonstrated benefit.

IPhreeqc is retained as a restricted aqueous-equilibrium adapter behind interfaces/model identity. The ideal root is an independently labeled reference. Arbitrary LLM guesses and experiment-specific reaction tables do not satisfy scientific behavior. Extension packages/providers permit additional domains without claiming they exist now.

One material authority and mode adapters prevent divergent VR/desktop chemistry. Data-driven stock/tool/protocol definitions support new content; scientific capability changes still require evidence and version identity. SaaS/billing/cloud can follow actual institutional demand without blocking the offline core or becoming untested scaffolding.
