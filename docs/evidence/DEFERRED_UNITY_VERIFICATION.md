# PharmaLabVR — DEFERRED UNITY VERIFICATION REGISTER

**Source policy:** Full software implementation first; one coordinated real Unity validation campaign at the end. This file is an execution checklist, **not** a test report. It was populated from the live canonical `docs/evidence/execution-state.json` containing **66 tasks across P00–P24**.

**Unity target:** Unity 6000.3.25f1 (pinned `unity/ProjectSettings/ProjectVersion.txt`), OpenXR / XRI 3.3.2, WindowsDesktop, WindowsVR, AndroidVR. **No physical headset evidence** at the new implementation SHAs. `NOT_RUN` means that exact pending verification was not executed in the final integrated campaign, even if a prior phase has historical Unity evidence on an older SHA. `CodeImplemented`, `PendingUnityVerification`, `UnityVerified` and `AcceptedPlanner` are separate development/evidence states; the official ledger enum is unchanged.

## How local Codex should run the final campaign

1. Fetch the exact future final feature HEAD, keep PR #1 open; inspect `AGENTS.md`, repo `docs/evidence/NEXT.md`, the complete ledger and the original v2 task requirements. Verify the Unity Editor version and packages with a license-supported editor installation.
2. Configure and build native Windows x64 plugin and pinned IPhreeqc/identical database bytes before Player startup; stage the DLL into Unity's supported plugin directory. For Android, cross-compile ARM64 compatible .so, stage with correct importer CPU/platform settings; do not disguise a desktop binary as Android.
3. Generate assets/scenes with `PharmaLabVR.Editor.BuildPipelineEntry.AllAssets` in `-batchmode -nographics` first, inspect import/compile logs and asset GUID references; do not continue if compilation or serialized references fail.
4. Execute EditMode then PlayMode through actual Unity Test Runner in batchmode. Representative invocation from repository root (adjust Unity executable location on target workstation):

```powershell
& $UnityExe -batchmode -nographics -quit -projectPath unity -runTests -testPlatform editmode -testResults artifacts/deferred-unity/editmode.xml -logFile artifacts/deferred-unity/editmode.log
& $UnityExe -batchmode -nographics -quit -projectPath unity -runTests -testPlatform playmode -testResults artifacts/deferred-unity/playmode.xml -logFile artifacts/deferred-unity/playmode.log
```

5. Execute real `BuildPipelineEntry.WindowsDesktop`, `WindowsVR`, `AndroidVR` after successful package staging and actual Unity compilation; preserve fresh binary SHA-256 and full nonzero-exit-aware logs.
6. Drive **actual** UI input: Home→Setup→Lab→Inspect→Measure→Pause→Hold/Continue→Review, save/load with native export receipts. Capture WindowsDesktop at **640×400**, **1280×720**, **1920×1080**; the small-window layout was previously clipped.
7. Test **XR ray** target→trigger→EventSystem→Button→shared router; verify exactly one active EventSystem/input module, valve/tool events suppressed while UI owns press. Clearly distinguish official XR simulator/injected-input evidence from physical controller/headset proof.
8. For each task, store EditMode/PlayMode XML, Player log, rendered screenshots/video, native event/material receipt deltas and binary hashes under its artifact folder below. Record actual date, Unity version, profile, test exit and final code SHA. Only then replace `NOT_RUN` with independently reviewed evidence and request planner grading; do not self-assign `AcceptedPlanner`.

**Global Native Core invariants:** native session retains material inventory and science authority; UI state is presentation only; mode/locale/help cannot edit pools; pH/model output is pinned, support/freshness/revision truthful; rejected commands never mutate; holds freeze transport and do not falsely Continue; recorded Review is not Save and never recomputes silently.
