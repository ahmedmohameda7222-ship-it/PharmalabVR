# P11.01 — Explicit Native checkpoint boundary (2026-10-17)

**Formal:** P11.01 Open/NotReviewed; release gate G-R1 Open. English-only. PR #1 unmerged. This is a Native code-first increment; integrated Unity testing **NOT_RUN**.

## Actual implementation

- `plv::DurableCheckpointStore` in `native/core/src/checkpoint.cpp`: bounded Native export payload in a versioned `PLV-CKPT-V1` framed format. Each checkpoint stores its sequence and byte length inside a SHA-256-covered header and payload, in two alternating disk slots. A staged temporary file is flushed by `fflush` and `fsync` (Ubuntu) or `_commit` (Windows) before renaming into the **inactive** generation; POSIX also fsyncs the containing directory. The last intact slot is recovered if a newer slot is damaged. Both damaged slots refuse recovery. A leftover `.tmp` does not count as committed. This is integrity checking, **not authentication**.
- `plv_checkpoint(handle,path)`: explicit Native ABI operation, locks actual Native session, writes its `exportJson` including branch, material, command receipts, model identity and checkpoint state. Successful return means the store's confirmed filesystem path; no simulation advance, new command receipt or hidden SaveService mutation. Source Native tests use a true `plv_create` / `plv_submit` / `plv_poll` live context, not a fabricated model snapshot.
- `plv_import_checkpoint(path,new_handle)`: a **separate** Native context, after reading the last checksum-valid slot and invoking the existing strict `plv_import` scientific-package, material and receipt validators. Never load/replay a corrupt slot, never silently replace a live Native session, no automatic recomputation on missing model.
- Unity source `CoreSession.WriteNativeCheckpoint` and `NativeMethods.Checkpoint` P/Invoke created, with source EditMode `P11_01_ExplicitNativeCheckpointPersistsRealNativeExportWithoutChemistryMutation`. Authored only: Unity Editor, PlayMode, Player and tracked XR NOT_RUN.

## Non-negotiable limitations

This is **explicit checkpoint only**. `DirtyCheckpointPolicy` is not yet connected to Native `plv_step` / `plv_submit` and automatic 30wall/30sim checkpoint writes. Receipt WAL is a separate primitive; there is no complete crash-consistent command journal/checkpoint transaction or concurrent multi-process lock. Windows file contents are flushed but directory-rename metadata power-loss resilience is unproven. No actual pulled-power, disk-full, arbitrary data corruption, unknown-model Unity or Player/XR campaign has run. No P11.01 or G-R1 acceptance and no release claim.

## 2026-10-17 — Scientific pinning and active authority safety correction

**Critical finding:** Prior descriptions suggesting that merely calling `plv_import` verifies *installed scientific database bytes* were too broad. The original Native `plv_import` validates stored scientific package metadata and command/material schemas but creates its IPhreeqc worker lazily, whereas `CoreSession.ImportSession` performs explicit C# pinned-file verification. New direct `plv_import_checkpoint` needed the same safety boundary *before* accepting a live context.

- RED test `76f24464c0196fbedb08d8d3b884f09ad016d464`: genuine checksummed `.slot0` wrapping a saved Native export with a declared pinned SHA but nonexistent database path.
