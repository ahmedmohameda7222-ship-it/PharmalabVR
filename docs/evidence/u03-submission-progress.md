## Submission security contract
Student must have fresh email-verified Auth and active student membership of supplied tenant; no writable role claims in JWT. SQL locks active membership, published assignment, enrollment, and owned cloud session; tests required lesson and rubric publication, deadline, nonzero Native revision and SHA-256 syntax. Ingestion cannot proceed on hash/JSON alone: requires an immutable, server-owned `session_artifacts` row matching student/session/hash and a corresponding actual private `storage.objects` object (JSON/ZIP). A unique attempt index rejects silent reuse of a Native branch for the same assignment; duplicate idempotency key returns the original submission UUID only when the audited payload matches, else fails. Every accepted attempt creates one append-only `SubmissionCreated` audit event. The production Native C++17 solver remains the authority for scientific state.
