# P00-P16 task reviews

Every entry records the required Plan, Review, Critic, and Alternatives/Long-term pass. “Partial” and “source-only” are intentional evidence states, not completion claims.

## P00 — Environment and authority

**Plan:** Verify the package, establish the named repository and isolated feature branch, retain v3 authority, and record prerequisites. **Review:** Package verification passed and the environment doctor is test-covered. **Critic:** The local host lacks CMake/C++, Unity, and VR hardware. **Alternatives/long term:** Use hosted native compilers, keep Unity evidence blocked, and never publish source references.

## P01 — Native contract foundation

**Plan:** Define a stable JSON C ABI before implementation. **Review:** ABI lifecycle, exact NUL sizing, UTF-8 boundary, queue polling, and snapshot operations compile and pass on Windows/Linux. **Critic:** Schema coverage and fuzzing are narrower than the full contract. **Alternatives/long term:** Generate schema bindings and add sanitizer/fuzz jobs without changing ABI 1.

## P02 — Material authority

**Plan:** Make a native state executor authoritative for vessels, water, components, capacity, revision, and conservation. **Review:** Deterministic creation, rejection, and round-trip tests pass. **Critic:** Solids, gas, residue, solubility, density models, and advanced inventory operations are absent. **Alternatives/long term:** Add explicit phase pools and migrations; never infer mass from presentation state.

## P03 — Transport

**Plan:** Implement fixed-volume transfers atomically against authoritative state. **Review:** capacity rejection and conservation tests pass. **Critic:** live flow, sampled input ownership, holds, scheduler, disconnects, and residuals are not implemented. **Alternatives/long term:** extend the command/event model while retaining all-or-nothing conservation and replayable ordering.

## P04 — Scientific adapter

**Plan:** Separate state authority from a deterministic aqueous observation adapter and verify against packaged fixtures. **Review:** 40 ideal cases pass independently and in native tests. **Critic:** the production IPhreeqc adapter is not integrated; vendor source presence is not an implementation. **Alternatives/long term:** build the pinned engine behind the same adapter, record provenance, and cross-check both paths.

## P05 — Scheduler, holds, and instruments

**Plan:** Reserve authoritative time/revision/event boundaries. **Review:** revisioned commands and bounded events exist. **Critic:** the scheduler, analytical holds, instrument models, and metrology tests are absent. **Alternatives/long term:** implement these natively before adding visual instrument behavior.

## P06 — Unity integration

**Plan:** Pin Unity packages and provide C ABI lifecycle/build entry points. **Review:** source contains SafeHandle interop, 20 ms driver, scenes generator, and strict build functions. **Critic:** it has not been imported or compiled by Unity and no package lock or serialized output exists. **Alternatives/long term:** run AllAssets first in the pinned Editor, inspect serialized references, then run EditMode/PlayMode suites.

## P07 — XR rig and geometry

**Plan:** Map XR controller poses into common lab-frame samples and keep XR inactive unless selected. **Review:** the adapter shares the geometry function tested against desktop samples and fails closed on unbound transforms. **Critic:** no real XRI rig, actions, prefabs, ownership manager, or simulator journey exists. **Alternatives/long term:** author inspectable XRI assets and test simulator/headset parity using the same command stream.

## P08 — Tools and visual truth

**Plan:** Keep tool mechanics subordinate to native state. **Review:** no unsupported tool completion claim is made. **Critic:** the required authored tools, residue behavior, visuals, and visual-truth tests are absent. **Alternatives/long term:** implement tools after transport/scheduler authority and test rendered state against snapshots.

## P09 — XR deployment variants

**Plan:** Pin OpenXR/XRI and expose Windows VR, Android VR, and Pico research build entry points. **Review:** package configuration and strict target methods exist. **Critic:** loader/features, Android toolchain, signing, IL2CPP, runtime, and device checks are unverified. **Alternatives/long term:** qualify one vendor-neutral Android path first and keep Pico isolated as a research profile.

## P10 — Desktop, UI, and localization

**Plan:** use the same native core with mouse/keyboard sampling and English/Arabic data. **Review:** desktop adapter, focus hold, localization tables, and shared geometry exist in source. **Critic:** no complete camera/tool journey, boot selector, polished panels, TMP Arabic font/shaping, RTL layout, accessibility pass, or screenshot exists. **Alternatives/long term:** build desktop-first interaction tests in the Editor while preserving input parity.

## P11 — Persistence

**Plan:** use atomic local saves with an explicit schema envelope. **Review:** source writes a temporary file with write-through/flush and atomic replacement. **Critic:** journal durability, migrations, recovery, replay, corrupt-tail handling, and crash/fault injection are absent. **Alternatives/long term:** make the native journal authoritative and treat Unity saves as indexed presentation metadata.

## P12 — Research protocols

**Plan:** encode protocol limitations and capability gates rather than imply validity. **Review:** two research-only protocol definitions and capability-gate source exist. **Critic:** no executable protocol runner, assay scoring, counterbalancing, audit chain, signed export, or validation evidence exists. **Alternatives/long term:** require explicit approval before certified scoring or claims and version every protocol/export schema.

## P13 — Testing and CI

**Plan:** run native tests on Windows/Linux and independent fixture verification. **Review:** exact-head hosted jobs pass and retain tested binaries. **Critic:** Unity tests/builds, sanitizers, fuzzing, Android, simulator, and hardware lanes are missing. **Alternatives/long term:** add license-aware Unity CI and separate simulator/device evidence lanes.

## P14 — Performance and acceptance

**Plan:** define per-target acceptance records and a Unity performance recorder. **Review:** target JSON files remain BuildNotVerified and recorder source exists. **Critic:** no actual Player metrics, timing calibration, soak, thermal, memory, or power evidence exists. **Alternatives/long term:** record raw captures from each real target and fail acceptance on missing required evidence.

## P15 — Evidence pack

**Plan:** keep evidence machine-readable and distinguish tested native results from blocked Unity/device results. **Review:** environment, progress, target acceptance, decisions, and review records are committed. **Critic:** no actual screenshots or Player artifacts can be supplied. **Alternatives/long term:** append immutable artifact hashes, logs, images, and hardware identifiers after real runs.

## P16 — Delivery

**Plan:** push the named branch, require exact-head CI, and open an unmerged review PR. **Review:** branch pushes and CI are real; final PR identity is recorded externally once created. **Critic:** this delivery is partial against the complete P00-P16 contract. **Alternatives/long term:** continue on the same branch/PR and never replace missing evidence with declarations.
