# Deep understanding and four useful workspaces

## Learning loop
Objective and capability → prediction → actual preparation/action → observation with status → student interpretation → model-supported explanation → compare repeats → review mistakes.
Store the student's hypothesis and confidence before action. They cannot influence chemistry. Hints progress from a technique clue to an explanation; used assistance is recorded. Overshoot, spills, incorrect preparation and contamination retain real material consequences. System faults do not lower a student error score.

Teach supported concepts through on-demand views: represented-pool conservation versus speciation; dilution; acetate buffer behavior; instrument reading versus cumulative delivered volume; contamination and rinse; observation freshness versus model maturity; ideal versus engine assumptions. Species diagrams, conservation ledgers and curves are optional explanation views. Reading-skill mode does not reveal the correct numeric volume. Actual plots consume valid observations; predicted/counterfactual plots declare the model and assumptions.

## Student workspace
Guided or independent practice, optional orientation, clear objectives, prediction journal, hands-on manipulation, observation prompts, hint tiers and a post-run explanation. Allow exploration and repetition without forced endpoints or automatically positioned receivers. English/Arabic, seated/left-handed reach, captions, text scale and control help are functional requirements. Review records what the learner actually did and which support they used.

## Instructor workspace
Build a local course and versioned lessons: objectives, required capabilities, allowed station/materials/equipment, preparation, steps, questions, hints, rubric, student preview and export. Rubrics inspect events and student entries, not artificial chemical outcomes. Keep technique, scientific reasoning and instrument-reading objectives distinct. Review an actual attempt with its prediction, measurements, spills/refills, assistance, timeline and notes. Add feedback and export a summary. Research examples remain ungraded when the required validation or assessment evidence is absent.

## Research workspace
Projects contain hypotheses, variables, fixed conditions and model identity. Save/checkpoint/fork, repeat actual runs, compare valid observations/material quantities and annotate events. Export CSV/JSON with units, revisions, assumptions, uncertainty and source identities. Changed parameters must pass provider coverage. Simulated and measured reference data remain distinct. Recomputing with a different model creates an explicit comparison, preserving original recorded history.

## Expert/pharmacist workspace
Minimal guidance with the same physical laboratory and authority. Fast station/compound/equipment selection, explicit preparation and model boundaries, notebook and reproducible comparisons. Expert use never silently bypasses budgets, unsupported science or material accounting. Optional explanations remain available. This is a pharmaceutical laboratory workspace, not a clinical treatment/dosing service.

## University value and acceptance
Local versioned course packs, bilingual accessible practice, supported skill objectives, instructor review/export, installation/hardware documentation and formative pilot evidence. No compulsory cloud login. SSO/LMS/multiplayer/fleet integrations are separate future work; do not create fake enterprise buttons.
An institutional demonstration must show an actual learner practice, a teacher-authored lesson with reviewed attempt, and a researcher comparison/export. It cannot be only a room tour. Test teacher export/reimport, invalid capability/rubric combinations, stale-data explanation gates, mixed Arabic scientific notation and assistance eligibility. Gather the original 5–8 formative participants where available; no fabricated participants, university approval or accreditation.
