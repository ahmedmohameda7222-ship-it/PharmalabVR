## Task state and continue
Copy tracker template to repository docs/evidence/execution-state.json once, then maintain it. Preserve resolved tasks on subsequent turns; do not replace it with the pristine template. Store planId/taskId/actualHEAD/code SHA/status/evidence/next/blocker in every checkpoint. User `continue` means read state + git status + NEXT.md and resume the first eligible task, fix its regression then continue. Never restart P00, stop after writing a plan, or treat an earlier build as finishing a later task.

Statuses: Open, InProgress, Implemented, VerifiedLocal, Failed, BlockedExternal. PlannerStatus is separate: NotReviewed, ChangesRequested, AcceptedPlanner. Only explicit planner review can grant AcceptedPlanner. Implemented means connected runtime behavior; unit helper or prefab-only scaffold cannot pass a journey task. VerifiedLocal requires all applicable task-local software/scene evidence. A phase may have local verification while physical/experimental/human gates remain pending. Missing scientific validation is not approval for a Published claim. Original95 retains its required scope. No percentages computed from test-count/task-count.

## Per-task contract
Read original requirements and relevant review. Credit completed code. Reproduce bugs before fixes; test domain/integration behavior. Implement focused runtime path and rendered view. Check relevant native/Unity tests, actual input-driven journey where applicable, data/schema/license identities. Write Plan/Review/Critic/Long-term decision note briefly. Commit reviewable work, record evidence, update NEXT and continue. Do not add fake aliases/buttons/statuses merely to satisfy a checklist. Do not keep rerunning all tests without a changed concern; phase/milestone regression is sufficient.

## Milestones and stopping
M0 Baseline+known correctness defects resolved; M1 P08.04 real premium operating bay; M2 P00-P13 core learning+Review+Arabic usable; M3 P17 catalog +P23 teacher/research workspaces; M4 all claimed expanded packs and P24 audited. Milestone reports are concrete checkpoints; they do not stop independent coding. If the turn ends or context compacts, flush a truthful NEXT.md and give the human the smallest continuation instruction; subsequent continue resumes. No background work after a turn is promised or scheduled.

A true external blocker includes unavailable physical device, missing needed licensed reference data or broken credentials. Record exact task/failed operation/source/action needed and preserve data; proceed to independent tasks, not dependent claims. A failed test, difficult UI, missing unfinished component or end of a build batch is unfinished work to fix, not an external blocker. Pack dependencies may be skipped only where independent: new model-source gaps never permit final acceptance of that pack.

## Handoff format after each turn
ExactHEAD; last finished task+proof; current task; next task; screenshot/recording if UI changed; tests run and actual scope; open failures/externalgates; proposed next concreteaction. Same branch/PR; local Windows implementation, commit/push authorized, no merge/force/reset/new redundant PR. Planner receives milestone/final evidence through the human; do not message another chat without human authorization.
